🛡 Happy Security Guard Simulator

A level-based simulation game where players act as a nightclub security guard, inspecting NPCs and controlling access through rule-based decisions and hidden condition checks. Built as a solo project with a focus on modular interaction systems and scalable gameplay loops.

What I Built

  • Rule-driven guest inspection flow with pass/fail validation tied to restricted item detection
  • Tool-based interaction suite including metal scanner, hidden object detector, and grooming trimmer
  • Fail-state logic that enforces decision accuracy when restricted NPCs are incorrectly admitted
  • Dynamic interaction actions using playful tools such as water gun, bat, and bees
  • Inventory and confiscation loop that routes restricted items into sellable shop resources

Core Systems

  • Level progression framework with increasing NPC complexity and hidden-condition combinations
  • Inspection state manager handling queue flow, tool context, outcomes, and transition timing
  • Economy layer converting confiscated items into currency for tool and premium unlocks
  • Modular scenario definitions enabling fast authoring of diverse level objectives

AI & NPC Architecture

  • Scalable NPC handling manager coordinating queue behavior and inspection-ready states
  • Profile-based NPC data model combining appearance traits, hidden items, and behavior flags
  • Rule-evaluation pipeline that maps inspection outcomes to level pass/fail conditions
  • Event-driven response system for tool interactions, reactions, and post-inspection routing

Performance & Optimization

  • Object pooling for NPCs, interaction props, UI prompts, and reaction effects
  • Manager-driven update architecture reducing per-entity overhead in high-throughput levels
  • Data-driven level and NPC configuration to scale content without scene duplication
  • Optimized interaction dispatch for responsive tool use and consistent decision feedback

Tools & Technologies

  • Unity (C#)
  • Custom interaction and inspection systems
  • Rule-based gameplay validation architecture
  • Object pooling and manager-driven runtime systems
  • ScriptableObject-based level and NPC definitions

My Role

  • Sole developer responsible for systems architecture, implementation, and balancing
  • Designed and built inspection mechanics, interaction tools, and decision validation logic
  • Implemented progression, economy, and unlock systems for long-term gameplay expansion
  • Developed modular content workflows for scalable level and NPC scenario production
